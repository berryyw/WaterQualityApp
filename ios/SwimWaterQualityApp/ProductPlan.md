# 泳池水质通产品方案

## 1. 产品概述

- 产品名称：泳池水质通
- 平台：`iOS 17+`
- 视觉方向：参考 `iOS 27.0` 原生设计语言，强调清晰层级、半透明材质、地图与卡片融合体验
- 产品定位：围绕“附近游泳馆水质信息查询”的城市生活工具 App
- 核心价值：帮助用户在出发前快速判断“附近哪家泳馆更适合去”，把地图找馆、水质判断、关注管理和用户评价放到一个闭环里
- 城市策略：产品能力按全国范围设计，默认城市为北京，支持用户主动切换城市

## 2. 目标用户

- 学生用户：放学后、周末或假期临时寻找适合游泳的场馆
- 家长用户：为孩子选择更安全、更放心的泳馆
- 固定健身用户：希望长期关注几家常去泳馆，并持续查看水质变化
- 新到城市用户：希望基于地图和搜索快速了解附近泳馆情况

## 3. 目标问题

- 现有地图或生活服务平台偏重地址、价格和评分，缺少“水质是否达标”的核心判断
- 用户需要在多个来源之间切换，才能拼凑出场馆信息、水质数据和用户口碑
- 缺少持续关注机制，无法方便地追踪某几家泳馆的热度和最新状态
- 当用户到陌生城区或切换城市时，查找附近泳馆的路径不够直观

## 4. 版本范围

- 支持邮箱注册、验证码登录、首次设置密码
- 登录后展示三个底部 Tab：`地图`、`热度`、`我的`
- 地图页基于 `Apple Map / MapKit` 展示泳馆位置、名称和搜索入口
- 泳馆详情页展示基础信息、水质信息和用户评价信息
- 支持关注 / 取消关注泳馆
- 热度页展示同城内按关注人数降序排序的泳馆列表
- 我的页展示用户头像、昵称、邮箱和我的关注入口
- 全国范围城市架构，首版默认北京，并支持城市切换

## 5. 注册与登录

### 注册登录目标

- 使用邮箱作为账号主体，降低手机号注册门槛，便于学生用户和跨设备登录
- 将“验证码验证邮箱”作为首次登录的安全确认方式
- 在完成验证码校验后，引导用户设置登录密码，形成后续稳定登录能力

### 账号流程

1. 用户输入邮箱并发起注册
2. 系统向用户邮箱发送验证码邮件
3. 用户输入邮箱和验证码完成首次登录
4. 用户首次登录后设置密码
5. 后续日常登录统一使用邮箱 + 密码登录
6. 当用户修改邮箱或修改密码时，需要再次通过验证码完成安全校验

### 账号规则

- 邮箱要求：符合标准邮箱格式
- 验证码要求：6 位数字验证码，建议 10 分钟内有效
- 验证码使用场景：首次登录、修改邮箱、修改密码
- 密码规则：固定为 `8-20` 位，且至少包含字母和数字
- 安全策略：连续多次验证码或密码失败后触发短时风控限制

## 6. 信息架构

- 登录前：欢迎页、邮箱注册 / 登录页、验证码验证页、设置密码页、密码登录页
- 登录后 Tab 1：地图
- 登录后 Tab 2：热度
- 登录后 Tab 3：我的
- 全局二级页：泳馆详情页、我的关注列表页、编辑昵称页、上传头像入口、城市选择页、修改邮箱页、修改密码页、验证码确认页

## 7. 核心用户流程

1. 用户首次进入 App，完成邮箱注册和验证码验证
2. 首次登录成功后设置密码，进入主界面
3. 默认进入 `地图` Tab，查看北京当前区域内的泳馆标注
4. 用户可通过顶部搜索框搜索泳馆名称，或通过地图点选某个泳馆
5. 进入泳馆详情页，查看基础信息、水质指标和用户评价
6. 用户可在详情页关注该泳馆，后续在 `我的关注` 中集中查看
7. 用户切换到 `热度` Tab，查看当前城市内关注度最高的泳馆列表
8. 用户进入 `我的` Tab，管理头像、昵称、邮箱和已关注泳馆

## 8. 页面说明

### 地图

- 底层地图服务：`Apple Map / MapKit`
- 页面元素：城市切换、搜索框、地图标注、泳馆名称标签、当前位置入口
- 页面目标：围绕“就近发现泳馆”建立第一入口
- 主要交互：
- 点击搜索框，搜索泳馆名称，并跳转到详情页
- 点击地图上的具体泳馆标注，进入详情页
- 详情页支持返回上一页

### 热度

- 页面目标：帮助用户快速发现同城内受关注度高的泳馆
- 排序方式：按当前城市内泳馆关注人数从高到低排序
- 列表字段：泳馆图片、泳馆名称、关注人数总数、简短标签
- 主要交互：点击任一列表项进入泳馆详情页

### 我的

- 页面目标：统一管理账号资料和关注关系
- 页面字段：用户头像、用户昵称、用户邮箱、我的关注入口
- 主要交互：
- 点击头像，上传或更换头像
- 点击昵称，进入编辑页并保存昵称
- 点击“我的关注”，查看已关注泳馆列表

### 我的关注

- 列表字段：泳馆图片、泳馆名称、关注人数总数、城市或区域信息
- 主要交互：点击某一行进入对应泳馆详情页

### 泳馆详情

- 支持从地图页、热度页、我的关注列表页进入
- 支持返回上一页
- 支持关注 / 取消关注

## 9. 泳馆详情信息结构

### 第一部分：基础信息

- 游泳馆名称
- 游泳馆图片
- 地址位置
- 坐标信息

### 第二部分：水质信息

- 物理性指标：
- 浑浊度 `Turbidity`
- 水温 `Water Temperature`
- 化学性指标：
- `PH`
- 游离性余氯 `Free Chlorine`
- 化合性余氯 `Combined Chlorine`
- 氧化还原电位 `ORP`
- 微生物指标：
- 菌落总数
- 总大肠菌群
- 其他指标：
- 尿素 `Urea`
- 氰尿酸 `Cyanuric Acid`
- 溶解性总固体 `TDS`
- 水质更新时间

### 第三部分：用户评价

- 用户头像
- 用户名称
- 评价内容
- 评价时间

## 10. 核心数据模型

- 用户：用户 ID、邮箱、昵称、头像 URL、密码摘要、注册时间、最近登录时间
- 城市：城市 ID、城市名称、城市中心点、默认地图区域
- 泳馆：泳馆 ID、名称、封面图、地址、经纬度、所属城市、关注总数
- 水质数据：泳馆 ID、检测时间、指标名称、指标值、单位、状态说明
- 评价：评价 ID、用户 ID、用户头像、用户昵称、评价内容、评价时间、泳馆 ID
- 关注关系：用户 ID、泳馆 ID、关注时间

## 11. 交互与体验原则

- 首屏优先地图，保证“附近泳馆”心智足够明确
- 搜索和地图点选都应在两步内到达详情页
- 泳馆详情页优先突出水质信息，其次展示基础信息和用户评价
- `热度` 与 `我的关注` 应以列表效率优先，减少多余操作层级
- 登录流程尽量轻量，首登完成邮箱验证后立即引导完成密码设置

## 12. 技术与后端建议

- 客户端地图能力使用 `MapKit`
- 邮箱验证码需依赖服务端邮件发送能力，例如 `SMTP` 或第三方邮件服务
- 账号体系需提供注册、验证码校验、设置密码、登录和用户资料更新接口
- 水质数据建议采用“泳馆主表 + 检测记录表”的结构，便于后续接入真实监测数据
- 关注人数与热度榜单建议由服务端聚合，客户端只负责展示

## 13. 后续演进

- 增加同城排行榜更多维度，如评分、最近热度增长、学生友好度
- 增加路线导航、到馆时间估算和营业时段提醒
- 增加泳馆图片相册和用户多图评价
- 接入真实政府公开数据或第三方场馆数据源
- 扩展到全国重点城市，并逐步实现更细粒度的区域搜索
